# Phase 2: 目标 + 范围 (Goal & Scope)

> **所属技能**：`eas-dev-align`
> **目标**：明确"做什么 / 不做什么"——本次工作的边界。
> **必答对应**：`behavior.gate.phases[1]`（phase-2-scope）
> **前置依赖**：Phase 1 完成

---

## 目标 (Goal)

让 Agent 明确本次工作的**边界**——是属于全新模块 / 扩展已有 / 重构？边界决定下游技能的工作模式（新设计 vs 增量 vs 改造）。

## 怎么问 (How to Ask)

**主问题**：`behavior.gate.phases[1].question`：

> "本次工作的范围边界在哪？"

**预设选项**（来自 `behavior.gate.phases[1].options`）：

| 选项              | 含义         | 下游影响                                   |
| ----------------- | ------------ | ------------------------------------------ |
| `greenfield`      | 全新模块     | 可用最新模式；不受历史约束；需更多设计时间 |
| `extend-existing` | 扩展已有模块 | 受现有接口约束；向后兼容性优先             |
| `refactor`        | 重构已有代码 | 行为不变；可分阶段迁移；测试覆盖必须先到位 |
| `other`           | 其他         | 用户自定义补充                             |

## 输入 (Input)

- Phase 1 输出的动机 / 利益相关方 / 不做的风险
- 用户对工作范围的描述

## 输出 (Output)

**Phase 2 输出项**（写入 `alignment.md` 的"目标"和"范围"章节）：

### 目标 (Goal)

- **Primary Goal**：本次工作要达成的核心目标（一句话）
- **Success Indicator**：成功的可观察标志（用户能看到的具体变化）

### 范围 (Scope)

**In-Scope**（必做清单）：

- [ ] 明确的子功能 1
- [ ] 明确的子功能 2
- ...

**Out-of-Scope**（明确不做）：

- ❌ 不做的子功能 A（理由）
- ❌ 不做的子功能 B（理由）
- ...

**Adjacent / Future**（相邻 / 未来）：

- 暂不做的功能 X（但需要预留接口）
- 计划下个迭代做的功能 Y

## 示例 (Example)

**承接 Phase 1 示例**（客服找不到历史工单）：

> "本次工作的范围边界在哪？"
>
> - 🔘 全新模块（独立搜索服务）
> - 🔘 扩展已有模块（在工单服务内加搜索 API）
> - 🔘 重构已有代码（替换现有搜索实现）
> - 🔘 其他

**用户选择**："扩展已有模块"

**Agent 追问**：

- "具体加在哪个模块？" → "工单服务的 read API"
- "哪些字段可搜索？" → "标题 / 内容 / 标签 / 客户名"
- "哪些不算搜索范围？" → "按时间过滤（已有）/ 按状态过滤（已有）"

**Phase 2 输出**：

```yaml
goal:
  primary: 在工单服务增加全文搜索能力
  success_indicator: 客服查找工单时间从 5 分钟降到 30 秒

scope:
  in_scope:
    - 工单标题 / 内容 / 标签 / 客户名的全文搜索
    - 返回结果按相关性排序
    - 支持中文 / 英文混合
  out_of_scope:
    - 时间范围过滤（已有功能，不重复）
    - 状态过滤（已有功能，不重复）
    - AI 增强搜索（下一迭代）
  adjacent:
    - 预留搜索结果高亮接口（为未来 AI 增强准备）
```

## 反模式 (Anti-Patterns)

| ❌ 不要                            | ✅ 应该                                        |
| ---------------------------------- | ---------------------------------------------- |
| 范围过宽（"所有工单字段都可搜索"） | 明确列出 3-7 项核心 in-scope 项                |
| 范围完全没限制（"做搜索就行"）     | 必有 out-of-scope 清单                         |
| 把"未来要做"塞进 in-scope          | 未来做的事放 adjacent；in-scope 必须当前可完成 |
| Agent 自己补充 in-scope            | 全部由用户确认；Agent 可建议但不能擅自加       |
